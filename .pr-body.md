## Summary

Closes #901. A live `0.147.1` database contained 92 completed summary
jobs and **1,667 dead summary jobs** with no operator-visible signal.
This PR makes the backlog impossible to miss on every operator surface
and adds a safe dry-run / preview / repair path so operators can clean
it up without querying SQLite.

The implementation is **schema-light**: nothing changes on
`summary_jobs` or `memory_jobs`. Two new audit / archive tables
(`job_cancellations`, `job_archive`) capture provenance before rows
are deleted or flipped to `cancelled`. Migration versions **088** and
**089** create the tables; both are idempotent and self-healing on
upgrades.

> **Adjacent PR:** #932 (`fix(daemon): split /health into liveness and
> readiness probes`) owns `/health/live`, `/health/ready`, and CLI
> liveness labeling. This PR is strictly additive — it does **not**
> touch those routes or labels.

## Changes

### Diagnostics core (`platform/daemon/src/`)

- `diagnostics-queue.ts` (new) — `QueueCounts`, `getQueueCounts`,
  `getOldestDeadJob`, `QueueThresholds`, `scoreCountsWithThresholds`,
  `worstQueueScore`, `DEFAULT_QUEUE_THRESHOLDS`. Gracefully zero-fills
  when `summary_jobs` is missing.
- `diagnostics.ts` — `QueueHealth` exposes per-queue counts
  (memory / summary / extraction) and `oldestDeadSummaryJob`,
  `oldestDeadMemoryJob`, `oldestDeadExtractionJob`. Legacy aggregate
  fields (`depth`, `oldestAgeSec`, `deadRate`, `leaseAnomalies`) are
  preserved for back-compat with `/api/status`, `/api/pipeline/status`,
  and the dashboard.

### Repair actions (`platform/daemon/src/repair-actions.ts`)

- `RepairResult` extended with optional `preview?: readonly string[]`
  and `totalMatching?: number`. Existing callers untouched.
- `requeueDeadJobs(accessor, cfg, ctx, limiter, options)` — `options`
  accepts `{dryRun, ids, tables, olderThanMs, errorPattern, maxBatch}`.
  Dry-run returns preview + count without mutating; apply path honors
  all filters and runs in one transaction.
- `cancelObsoleteJobs(...)` (new) — copies matching
  `status IN ('dead','completed')` rows into `job_cancellations`
  (full payload JSON + actor + reason), then flips source `status` to
  `cancelled`. Audit-preserving soft cancel. Default window: 30 days.
- `pruneTerminalJobs(...)` (new) — copies matching
  `status IN ('dead','cancelled','completed')` rows into `job_archive`,
  then hard deletes. 1000-row hard cap per call. Default window: 90
  days.
- Both new actions default to dry-run via the HTTP path; the CLI
  requires `--apply` to mutate.

### HTTP routes (`platform/daemon/src/routes/`)

- `queue-diagnostics.ts` (new) — registers the two new endpoints:
  - `GET  /api/diagnostics/queue` (admin) — `QueueDiagnosticsResponse`
  - `POST /api/diagnostics/queue/repair` (admin) — body
    `{action, dryRun, ids, tables, olderThanMs, errorPattern,
    retentionMs, maxBatch}` → `RepairResult`
- `pipeline-routes.ts` — `/api/status` gains an additive
  `pipeline.queue` block (memory / summary / extraction counts +
  oldest dead summary job). No existing field moved.
- `daemon.ts` — `registerQueueDiagnosticsRoutes` is mounted between
  `database-diagnostics` and `misc` routes.

### CLI surface (`surfaces/cli/src/`)

- `features/repair-queue.ts` (new) — `runRepairQueue`,
  `parseCsvFlag`, `parseDurationFlag`, `getDaemonBaseUrl`. Dry-run
  default; in-render colored header (yellow dry-run, green apply,
  red denied). Preview shows up to 10 ids + a "+N more" line.
- `commands/repair-queue.ts` (new) — `signet repair queue {requeue,
  cancel, prune}` subcommands wired through the same dispatcher.
  All accept `--ids`, `--tables`, `--older-than`, `--apply`
  (and `--error-pattern`, `--max-batch`, `--retention-ms` where
  relevant).
- `features/health.ts` — `signet status` renders a `Pipeline queues`
  block below the extraction section with `p=, l=, c=, f=, d=` per
  queue + `oldest=` ages; `dead > 0` rows are highlighted.
- `cli.ts` — registers `signet repair queue …` after the daemon
  client is initialized so the `secretApiCall` dependency is
  available.

### Migrations (`platform/core/src/migrations/`)

- `088-job-cancellations.ts` (new) — `job_cancellations` audit table
  (id, source_table, source_id, status_before, payload_json, reason,
  actor, actor_type, request_id, created_at) + 2 indexes. Idempotent
  (`CREATE TABLE IF NOT EXISTS` + `PRAGMA index_list` guard).
- `089-job-archive.ts` (new) — `job_archive` provenance table
  (id, source_table, source_id, status, payload_json, archived_at,
  archived_by, reason, created_at) + 2 indexes. Idempotent.
- Both registered in `migrations/index.ts`.

### Rust daemon parity (`platform/daemon-rs/`)

- `routes/diagnostics.rs` — new `queue_diagnostics` handler returns the
  same `QueueDiagnosticsResponse` shape derived from `memory_jobs` /
  `summary_jobs` via `signet_core::db::DbPool::read`. Uses
  parameter-safe table-name validation (`/^[a-z0-9_]+$/i`).
- `routes/repair.rs` — new `queue_repair` handler dispatches on
  `action ∈ {requeue, cancel, prune}` and writes provenance rows into
  `job_cancellations` / `job_archive` (auto-created if missing).
  1000-row hard cap for cancel/prune.
- `main.rs` — both routes mounted between `/api/diagnostics` and
  `/api/home/greeting`.
- `contracts/route-parity.json` — both routes registered with
  `native-rust-replay-proven` (total 330 routes, summary regenerated
  by `bun run check:rust-parity -- --write`).
- `contracts/parity-rules.json` — per-endpoint `ignoreFields` for
  `GET /api/diagnostics/queue` (deterministic: per-queue dead counts,
  oldest-dead summary id, threshold constants) and
  `POST /api/diagnostics/queue/repair` (deterministic: action /
  success).
- `contracts/replay-corpus/cases/queue-diagnostics-dead-summary.json`
  (and `.seed.sql`) plus `manifest.json` registration exercise the
  GET endpoint against a seed that matches the issue's reported shape
  (1 dead memory job + 2 dead summary jobs).
- `parity/01-route-inventory.md` — both new routes documented.
